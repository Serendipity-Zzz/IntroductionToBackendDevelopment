# 接口设计与错误码

机器可读契约见[完整OpenAPI](09_接口契约.openapi.json)。以下描述当前完整工程，默认地址为http://127.0.0.1:8080；连接练习服务时通常改为8081。

## 通用约定

- 请求和响应使用JSON；退出成功为204，没有正文。
- 业务接口通过`Authorization: Bearer <token>`传递身份。token是不透明UUID字符串，不是JWT。
- 每次请求由服务生成X-Request-Id，业务错误正文也含requestId。不要把这个追踪ID当用户、活动或报名ID。
- 报名成功返回201，并带相对Location `/api/registrations/{id}`；注册账号返回201但不签发token，也没有该Location。
- 未知JSON正文字段会因配置被拒绝。路径ID须能解析为long，业务ID还须大于0。
- 示例账号、token和报名ID只帮助理解；串联接口时使用真实响应值。

## 入口清单

| 方法与路径 | 身份要求 | 输入 | 成功结果 |
|---|---|---|---|
| GET /health | 无 | 无 | 200，status=ok；不访问数据库 |
| POST /api/auth/register | 无 | username、displayName、password | 201，PublicUser |
| POST /api/auth/login | 无 | username、password | 200，token、user、expiresInSeconds |
| POST /api/auth/logout | 非空Bearer头 | 无正文 | 204，删除对应token；不要求该token仍有效 |
| GET /api/me | 有效token | 无 | 200，PublicUser |
| GET /api/events/{eventId} | 有效token | 正整数活动ID | 200，Event |
| POST /api/events/{eventId}/registrations | 有效token | 正整数活动ID，JSON {} | 201，Registration |
| GET /api/registrations/{registrationId} | 有效token | 正整数报名ID | 200，本人的Registration |
| GET /api/me/registrations | 有效token | 无 | 200，items数组，按报名ID倒序 |
| GET /api/events/{eventId}/my-registration | 有效token | 正整数活动ID | 200，本人该活动的Registration |

## 字段与校验

### 注册与登录

注册用户名先trim、转小写，再匹配`[a-z][a-z0-9_]{2,31}`。displayName先strip，再要求非空、最多32字符。新密码非空，长度8至64字符，UTF-8不超过72字节。字段名中的password不进入返回模型。

登录也归一化用户名，要求账号和密码非空，分别最多32、64字符；密码超过72字节按登录失败处理。旧演示密码demo123继续有效。成功响应expiresInSeconds为7200。

PublicUser：id、username、displayName。注册并不自动登录，需要接着调用login。

### 活动与报名

Event：id、title、capacity、registeredCount、remainingSeats、myRegistrationId。未报名时myRegistrationId为null；余量至少显示0。

Registration：id、eventId、eventTitle、userId、username、displayName、createdAt。createdAt为LocalDateTime对应的本地日期时间，不携带时区偏移。

RegistrationList：`{"items":[...]}`。报名正文必须是空对象，身份由后端取得；没有创建活动、管理用户或替别人报名的输入字段。

## 错误格式

```json
{
  "code": "REGISTRATION_NOT_FOUND",
  "message": "没有找到这条报名",
  "requestId": "本次响应中的追踪ID"
}
```

| HTTP | code | 当前含义 |
|---|---|---|
| 400 | VALIDATION_ERROR | 字段不合格、JSON格式/未知字段、ID格式或非正数 |
| 401 | UNAUTHENTICATED | 登录失败、缺少Bearer、会话失效或用户已不存在 |
| 404 | EVENT_NOT_FOUND | 指定活动不存在 |
| 404 | REGISTRATION_NOT_FOUND | 当前账号没有这条报名；包含其他用户拥有该ID的情况 |
| 404 | NOT_FOUND | 接口或静态资源不存在 |
| 405 | METHOD_NOT_ALLOWED | 请求方法不受支持 |
| 409 | USERNAME_TAKEN | 账号已存在，包括并发注册发生的唯一键冲突 |
| 409 | ALREADY_REGISTERED | 本人已报名 |
| 409 | EVENT_FULL | 活动容量已满 |
| 415 | UNSUPPORTED_MEDIA_TYPE | 请求正文没有使用受支持的JSON媒体类型 |
| 500 | INTERNAL_ERROR | 未预期的服务异常，按requestId查日志 |
| 501 | LAB_SQL_REQUIRED | 课堂SQL常量尚未填写；完整工程的常量已填好 |
| 503 | DATABASE_NOT_READY | 连接、库、表或SQL执行失败 |
| 503 | ACCOUNT_SCHEMA_UPDATE_REQUIRED | 旧库users.id未启用自增，须显式迁移 |

这里是控制器及错误处理器的约定。CORS拒绝等框架层响应可能是403或其他格式；不能假定所有失败都返回ApiError。

## 调试链

在Apifox环境设置base_url、event_id=10、username=myh、password=demo123。登录提取`$.token`与`$.user.id`；报名201后提取`$.id`为registration_id；后续GET按此ID查询并核对用户与活动。报名失败不能覆盖已保存的有效ID。

用myh（4）与活动10复现课堂故障：把新控制器的第二个参数传成eventId，会误查用户10而得到404；修成userId后，重建、重启、重登再请求，应查回同一条报名。
