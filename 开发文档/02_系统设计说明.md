# 系统设计说明

## 运行结构

```text
同源网页（Java提供静态文件） ─┐
独立前端（本机5500）        ├─ HTTP / JSON ─ Java服务 ─ JDBC / SQL ─ MySQL
Apifox                     ┘
```

Java服务由Spring Boot启动，内部用Spring MVC路由请求、Bean Validation校验字段、JdbcTemplate访问数据库。密码处理只使用spring-security-crypto；项目没有引入完整Spring Security Web鉴权链。

浏览器、Java、MySQL是不同职责。Controller、Service和Repository是同一Java程序内的组件，不是三台服务器。

## 组件与职责

| 文件 | 当前职责 |
|---|---|
| SignupApplication | 启动Spring Boot应用 |
| SignupController | 健康检查、注册登录退出、活动与报名查询、创建报名 |
| MyRegistrationController | 查询本人在指定活动的报名，传入eventId与登录userId |
| AuthService | 注册规则、BCrypt、UUID token、会话到期与登录身份解析 |
| SignupService | 活动检查、重复与容量判断、报名事务、本人查询 |
| SignupRepository | 参数化SQL、行锁、关联查询、自增ID回取 |
| Models | 请求与响应record，输入约束和账号归一化 |
| ApiErrorHandler | 业务与常见框架异常转换为状态码和错误JSON |
| RequestLogFilter | 每请求生成requestId，记录API方法、路径、状态和耗时 |
| LocalFrontendCorsConfig | 本机5500前端跨域配置 |

## 报名事务

`SignupService.register`由Controller通过Spring管理的Service调用，方法声明`@Transactional(isolation=READ_COMMITTED)`。

```text
校验正整数活动ID
  → SELECT活动行FOR UPDATE（不存在则404）
  → 查当前用户是否已经报名（是则409 ALREADY_REGISTERED）
  → COUNT活动报名，与capacity比较（满则409 EVENT_FULL）
  → INSERT(event_id,user_id)，取得生成的报名ID
  → 查回本人记录，事务提交后返回201
```

所有创建报名的请求都先锁同一活动行，使该活动的检查与写入按事务顺序进行。唯一键再限制同一用户重复，外键确保引用的用户和活动存在。只加唯一键不能限制活动总容量；只把按钮置灰也不能防止另一浏览器同时提交。

API没有提供修改活动容量的入口。若直接用SQL修改数据或绕过这条事务插入记录，属于额外操作，不应据此假定应用仍能保证全部业务规则。

## 登录与权限

登录成功时创建随机UUID字符串，映射到用户ID与绝对到期时间。映射放在进程内的ConcurrentHashMap，默认7200秒到期，不自动续期。多次登录会得到多个token；退出只删除指定的token。

受保护的业务方法调用`AuthService.require`，由token取用户，而不是接收客户端指定的用户ID。查询SQL还带user_id条件，查不到本人的记录时返回404。

退出接口只检查Bearer头是否存在且非空，不验证token仍在会话表中；已失效但格式正确的token再次退出也可204。这与查询接口要求有效会话不同。

## 数据保存范围

| 位置 | 保存内容 | 生命周期 |
|---|---|---|
| MySQL | 账号、哈希、活动、报名 | Java或页面重启后保留 |
| Java内存 | token到用户与到期时间的映射 | 服务重启清空 |
| 网页sessionStorage | 后端版的登录token | 当前浏览器标签页会话；不保存报名数据库 |
| 纯前端localStorage | 新注册的本机演示账号校验信息 | 当前浏览器保留，不跨浏览器共享 |
| 纯前端页面内存 | 报名记录 | 刷新或关页丢失 |

## 跨域与错误边界

仅`/api/**`允许来自`http://127.0.0.1:5500`及`http://localhost:5500`的GET、POST、OPTIONS。允许Content-Type与Authorization请求头，暴露Location和X-Request-Id，预检缓存3600秒。没有放开任意来源，也不使用跨域Cookie登录。

错误处理器负责控制器异常JSON；被CORS等框架层直接拒绝的请求，不保证遵循同一JSON结构。活动显示由多次查询组合，提交时仍以事务内结果为准。
