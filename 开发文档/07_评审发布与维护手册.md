# 评审发布与维护手册

当前交付方式是本机运行JAR及静态网页，没有实际生产部署或自动发布流水线。以下给出与现有项目相符的操作与检查，评审人、执行日期和结果应在真正执行时填写。

## 构建与配置

在完整工程目录执行：

```powershell
.\mvnw.cmd -DskipTests package
```

产物是target/signup-classroom-1.0.0.jar。Java编译目标21，依赖版本以pom.xml及Maven解析结果为准，当前Spring Boot为4.1.2。构建参数跳过测试，测试要单独按计划执行。

| 变量 | 完整工程默认值 | 说明 |
|---|---|---|
| DB_HOST | 127.0.0.1 | MySQL主机 |
| DB_PORT | 3306 | MySQL端口 |
| DB_NAME | signup_demo | 练习工程默认为signup_lab |
| DB_USER | workshop | 课堂数据库用户 |
| DB_PASSWORD | 空 | 实际运行必须填自己设置的密码 |
| DB_INIT | always | 完整工程自动运行schema.sql与data.sql；练习默认为never |
| SERVER_PORT | 8080 | 练习默认8081 |

服务固定监听127.0.0.1，未提供改变监听地址的环境变量。不能仅修改端口就视为已部署公网。

## 本机启动

先按00脚本准备数据库与workshop权限，已有旧库另执行03迁移。以下命令在完整工程目录运行，值换成自己的实际配置：

```powershell
$env:DB_HOST='127.0.0.1'
$env:DB_PORT='3306'
$env:DB_NAME='signup_demo'
$env:DB_USER='workshop'
$env:DB_PASSWORD='自己的课堂数据库密码'
java -jar target/signup-classroom-1.0.0.jar
```

也可双击材料根目录的快速启动/运行完整工程.cmd，交互输入连接信息。若更新完整工程源码，必须重新构建并核对快捷启动目录里的JAR，不能假定它会自动跟随源码变化。

健康检查GET /health为200只说明Java进程能响应。随后应登录、查活动、进行一次受控报名并查库，才覆盖数据库和业务路径。

## 评审与交付清单

- [ ] 记录源码基线、JAR SHA256和实际构建环境。
- [ ] 对照需求、OpenAPI、DDL和回归用例，完成一次当前版本验证。
- [ ] 若有迁移，记录目标库、备份位置、执行人和迁移后结果。
- [ ] 记录是否同时更新快速启动JAR及独立前端文件。
- [ ] 不把个人密码、测试数据库目录和浏览器缓存放进交付材料。
- [ ] 留下本次修改说明、已知限制与回退操作。

仓库版本号尚未区分注册功能加入前后，因此本次应同时记录日期与源码/JAR哈希。后续发布建议同步更新版本号，不只重命名JAR。

## 前后端分开联调

VS Code打开项目工程/前后端/fronted，用Live Server启动在http://127.0.0.1:5500；config.js默认请求http://127.0.0.1:8080/api，后端用8080启动。若改后端端口，同时改apiBase；若改前端端口，同时核对CORS允许来源。

纯前端对照可使用5501，它只演示本机状态，不应该给它放开后端跨域来“修复”对照实验。

## 回退

应用修改前保留已验证的上一份JAR及哈希。停止当前进程、换回旧JAR、用相同数据库配置启动，再进行登录与查询冒烟测试。每次Java重启都会清空会话，用户需要重新登录。

03迁移没有提供自动回退脚本。若旧代码与新增自增列兼容，可保留结构再退应用；若不兼容，应根据备份制定数据恢复方案。不要用DROP或删除数据库代替回退，也不要直接覆盖有新报名的数据。

## 运行与定位

RequestLogFilter输出requestId、方法、路径、状态、elapsedMs。数据库异常日志带requestId及异常类型；未预期错误记录堆栈。没有专用日志文件或日志轮转配置，默认观察Java控制台。

| 现象 | 操作顺序 |
|---|---|
| 端口占用 | 找到自己之前的运行窗口并停止；不随意结束其他服务 |
| 401 | 检查Bearer、到期和服务是否刚重启，重新登录 |
| 404 | 先区分NOT_FOUND、EVENT_NOT_FOUND和REGISTRATION_NOT_FOUND |
| 409 | 区分用户名占用、本人重复和活动满员 |
| 503 | 对照连接、库名、权限、建表与迁移；结合requestId查看日志 |
| 网页数据没更新 | 确认端口、库、运行的JAR及前端apiBase，修改后重新构建启动 |

进一步公网运行需要另行设计身份与会话、HTTPS、配置管理、访问限制、日志监控和备份恢复。它们属于后续建设，不能当成当前项目已具备的运维能力。
