需求规格与验收标准

目标与范围

让用户注册或使用演示账号登录，查看活动容量，提交一次报名，并查询自己的记录。多个用户争抢同一活动时不能超卖；关闭网页或重启Java后，已提交的账号与报名仍保留在MySQL。

当前系统服务于本机教学，包含普通用户和负责准备环境、导入SQL的讲师。没有独立管理员权限或管理后台；讲师操作数据库不等于系统实现了管理员角色。

业务需求

编号 规则与已实现行为 验收标准
R01 注册账号，用户名归一化为小写并保持唯一 合法注册201；大小写等价账号不能重复注册，返回409 USERNAME_TAKEN
R02 新账号密码8至64字符，UTF-8不超过72字节；称呼非空且最多32字符 短密码、空称呼或超限输入400；库中只存BCrypt哈希，响应不含密码或哈希
R03 注册后独立登录，凭证有效期7200秒 注册响应无token；正确登录200，错误密码401；重启服务后重新登录
R04 活动查询需要有效登录，显示容量、报名数、余量和本人的报名ID 已知活动200；未登录401；不存在的活动404 EVENT_NOT_FOUND
R05 报名身份来自后端登录态 报名正文为{}；不能通过附带userId替别人报名，未知正文字段400
R06 同一用户同一活动只能有一条报名 首次201；重复409 ALREADY_REGISTERED，记录数不增加
R07 活动报名总量不能超过capacity 容量1、初始无报名时两名用户并发，恰好一个201、一个409 EVENT_FULL，数据库只新增一行
R08 用户只能查询自己的报名 本人按ID查200；另一账号查同一ID返回404 REGISTRATION_NOT_FOUND
R09 可查自己的全部报名，以及自己在指定活动的报名 列表只含本人记录，按ID倒序；未报名的活动查询返回404
R10 账号与报名持久保存，登录会话临时保存 Java重启后旧token无效，重新登录后仍能找到原账号与报名
R11 支持本机独立前端联调 5500来源可按配置访问/api；未配置的5501来源不能跨域调用；同源网页正常使用

用户名注册规则是去掉首尾空白、转小写后满足[a-z][a-z0-9_]{2,31}。演示账号zhh、myh的密码demo123属于既有种子数据，允许继续登录；不能据此认为新注册也接受7字符密码。

主要用户流程

  1. 用户注册，或选择已有演示账号。
  2. 登录取得token，后续请求使用Authorization头。
  3. 查询活动；提交报名时由服务端重新检查身份、重复和容量。
  4. 成功后得到报名ID，查询记录并在网页显示。
  5. 退出时删除当前token；关闭页面后再登录，可以查回持久化记录。

边界与约定

  • 重复和满员同时成立时，先返回“已报名”，因为实现先检查本人记录。
  • 页面显示的余量只供展示，不是预留名额；提交时必须重新判断。
  • 活动由种子SQL准备，没有活动新增、修改、取消、支付、候补或报名撤销API。
  • 不提供找回密码、邮箱验证、账号禁用、Redis会话、JWT、自动刷新token或多实例一致性会话。

最小验收材料

保留注册与登录响应、一次报名201、重复与满员各一次409、本人和他人查询结果、数据库对应行，以及两账号并发结果。样例ID可以写成57，正式验收应使用接口真实返回的ID。

验收用例与已有记录见测试计划，需求到源码的对应见追踪矩阵。

系统设计说明

运行结构

同源网页（Java提供静态文件） ─┐
独立前端（本机5500）        ├─ HTTP / JSON ─ Java服务 ─ JDBC / SQL ─ MySQL
Apifox                     ┘

Java服务由Spring Boot启动，内部用Spring MVC路由请求、Bean Validation校验字段、JdbcTemplate访问数据库。密码处理只使用spring-security-crypto；项目没有引入完整Spring Security Web鉴权链。

浏览器、Java、MySQL是不同职责。Controller、Service和Repository是同一Java程序内的组件，不是三台服务器。

报名事务

SignupService.register由Controller通过Spring管理的Service调用，方法声明@Transactional(isolation=READ_COMMITTED)。

校验正整数活动ID
  → SELECT活动行FOR UPDATE（不存在则404）
  → 查当前用户是否已经报名（是则409 ALREADY_REGISTERED）
  → COUNT活动报名，与capacity比较（满则409 EVENT_FULL）
  → INSERT(event_id,user_id)，取得生成的报名ID
  → 查回本人记录，事务提交后返回201

所有创建报名的请求都先锁同一活动行，使该活动的检查与写入按事务顺序进行。唯一键再限制同一用户重复，外键确保引用的用户和活动存在。只加唯一键不能限制活动总容量；只把按钮置灰也不能防止另一浏览器同时提交。

API没有提供修改活动容量的入口。若直接用SQL修改数据或绕过这条事务插入记录，属于额外操作，不应据此假定应用仍能保证全部业务规则。

登录与权限

登录成功时创建随机UUID字符串，映射到用户ID与绝对到期时间。映射放在进程内的ConcurrentHashMap，默认7200秒到期，不自动续期。多次登录会得到多个token；退出只删除指定的token。

受保护的业务方法调用AuthService.require，由token取用户，而不是接收客户端指定的用户ID。查询SQL还带user_id条件，查不到本人的记录时返回404。

退出接口只检查Bearer头是否存在且非空，不验证token仍在会话表中；已失效但格式正确的token再次退出也可204。这与查询接口要求有效会话不同。

跨域与错误边界

仅/api/**允许来自http://127.0.0.1:5500及http://localhost:5500的GET、POST、OPTIONS。允许Content-Type与Authorization请求头，暴露Location和X-Request-Id，预检缓存3600秒。没有放开任意来源，也不使用跨域Cookie登录。

错误处理器负责控制器异常JSON；被CORS等框架层直接拒绝的请求，不保证遵循同一JSON结构。活动显示由多次查询组合，提交时仍以事务内结果为准。

关系

一个用户可以有多条报名，一场活动可以有多条报名。registrations把两者关联起来。活动容量不是报名表的行数上限约束，由应用事务判断。

SELECT r.id, u.username, e.title, r.created_at
FROM registrations r
JOIN users u ON u.id = r.user_id
JOIN events e ON e.id = r.event_id
WHERE r.event_id = 10;

旧库升级注册功能

CREATE TABLE IF NOT EXISTS不会修改已经存在的表。旧版users.id没有自增时，启动新程序仍可能登录，但注册插入会失败。

  1. 确认要升级的是自己的signup_demo或signup_lab，并备份这次课堂数据。
  2. 管理员连接选中对应库，先执行SELECT DATABASE()。
  3. 执行03脚本，给users.id增加AUTO_INCREMENT，保留原ID、账号与报名。
  4. 检查SHOW COLUMNS FROM users LIKE 'id'包含auto_increment；注册一个新账号并确认ID不覆盖既有账号。
  5. 确认原账号能登录、原报名仍在，错误外键引用仍被拒绝。

脚本临时关闭当前连接的FOREIGN_KEY_CHECKS，并恢复原值；若客户端在ALTER错误后停止，重新连接或按脚本提示恢复检查。workshop默认没有ALTER权限，不能用它代替管理员做这一步。

当前没有Flyway/Liquibase或自动版本化迁移。后续变更应新增编号SQL，写明备份、执行、验证和回退办法，不通过删库重建来升级已有数据。

演示账号现统一使用zhh、myh，密码均为demo123。旧账号保留。新建库中两个新账号的用户ID通常为3、4；已有库的编号可能不同，以登录响应user.id或按用户名查询的结果为准。旧库先在所用课堂库执行sql/04_新增演示账号.sql；如users.id尚未自增，先执行03升级脚本。

接口设计与错误码

机器可读契约见完整OpenAPI。以下描述当前完整工程，默认地址为http://127.0.0.1:8080；连接练习服务时通常改为8081。

通用约定

  • 请求和响应使用JSON；退出成功为204，没有正文。
  • 业务接口通过Authorization: Bearer <token>传递身份。token是不透明UUID字符串，不是JWT。
  • 每次请求由服务生成X-Request-Id，业务错误正文也含requestId。不要把这个追踪ID当用户、活动或报名ID。
  • 报名成功返回201，并带相对Location /api/registrations/{id}；注册账号返回201但不签发token，也没有该Location。
  • 未知JSON正文字段会因配置被拒绝。路径ID须能解析为long，业务ID还须大于0。
  • 示例账号、token和报名ID只帮助理解；串联接口时使用真实响应值。

字段与校验

注册与登录

注册用户名先trim、转小写，再匹配[a-z][a-z0-9_]{2,31}。displayName先strip，再要求非空、最多32字符。新密码非空，长度8至64字符，UTF-8不超过72字节。字段名中的password不进入返回模型。

登录也归一化用户名，要求账号和密码非空，分别最多32、64字符；密码超过72字节按登录失败处理。旧演示密码demo123继续有效。成功响应expiresInSeconds为7200。

PublicUser：id、username、displayName。注册并不自动登录，需要接着调用login。

活动与报名

Event：id、title、capacity、registeredCount、remainingSeats、myRegistrationId。未报名时myRegistrationId为null；余量至少显示0。

Registration：id、eventId、eventTitle、userId、username、displayName、createdAt。createdAt为LocalDateTime对应的本地日期时间，不携带时区偏移。

RegistrationList：{"items":[...]}。报名正文必须是空对象，身份由后端取得；没有创建活动、管理用户或替别人报名的输入字段。

错误格式

{
  "code": "REGISTRATION_NOT_FOUND",
  "message": "没有找到这条报名",
  "requestId": "本次响应中的追踪ID"
}
HTTP code 当前含义
400 VALIDATION_ERROR 字段不合格、JSON格式/未知字段、ID格式或非正数
401 UNAUTHENTICATED 登录失败、缺少Bearer、会话失效或用户已不存在
404 EVENT_NOT_FOUND 指定活动不存在
404 REGISTRATION_NOT_FOUND 当前账号没有这条报名；包含其他用户拥有该ID的情况
404 NOT_FOUND 接口或静态资源不存在
405 METHOD_NOT_ALLOWED 请求方法不受支持
409 USERNAME_TAKEN 账号已存在，包括并发注册发生的唯一键冲突
409 ALREADY_REGISTERED 本人已报名
409 EVENT_FULL 活动容量已满
415 UNSUPPORTED_MEDIA_TYPE 请求正文没有使用受支持的JSON媒体类型
500 INTERNAL_ERROR 未预期的服务异常，按requestId查日志
501 LAB_SQL_REQUIRED 课堂SQL常量尚未填写；完整工程的常量已填好
503 DATABASE_NOT_READY 连接、库、表或SQL执行失败
503 ACCOUNT_SCHEMA_UPDATE_REQUIRED 旧库users.id未启用自增，须显式迁移

这里是控制器及错误处理器的约定。CORS拒绝等框架层响应可能是403或其他格式；不能假定所有失败都返回ApiError。

调试链

开发规范与任务拆分

以下规范用于继续维护这份工程。现有实现作为例子，提交、分支和评审要求是建议的协作约定，不代表仓库已有完整团队流程。

代码组织与接口边界

  1. Controller接收请求和组织响应，不直接写SQL。新增HTTP入口放在对应Controller，参数和返回字段先同步接口契约。
  2. Service承载业务规则与事务；涉及容量的检查和写入必须在同一条受控事务路径中完成。
  3. Repository集中参数化SQL，用问号绑定输入。返回生成ID后再读取对应记录，不猜测自增ID。
  4. 请求和响应分开定义。PublicUser不能混用含passwordHash的内部User模型。
  5. 普通用户的身份从AuthService取得，不信任客户端的userId。按ID查询时还要带当前用户条件。
  6. 错误使用ApiException和既有错误码；新增错误同步接口说明与用例，避免所有异常都返回200。
  7. 配置和密码通过运行环境输入，Java、SQL、截图和日志中不粘贴真实密码或token。

命名与数据变更

  • Java方法与变量采用现有camelCase，例如eventId、userId；数据库使用snake_case，例如event_id。
  • eventId、userId、registrationId表达不同概念，即使类型同为long也不能互相替代。
  • 变更表结构时提供编号SQL与验证步骤，不能只改schema.sql后假定旧库自动升级。
  • 静态页面的config.js决定数据来源；调整独立前端地址时同步核对CORS，避免把纯前端对照变成真正API调用。
  • 保持完整工程为可运行参考答案；练习工程保留有意设置的断点，不把课堂错误控制器覆盖到完整工程。
