# 需求规格与验收标准

## 目标与范围

让用户注册或使用演示账号登录，查看活动容量，提交一次报名，并查询自己的记录。多个用户争抢同一活动时不能超卖；关闭网页或重启Java后，已提交的账号与报名仍保留在MySQL。

当前系统服务于本机教学，包含普通用户和负责准备环境、导入SQL的讲师。没有独立管理员权限或管理后台；讲师操作数据库不等于系统实现了管理员角色。

## 业务需求

| 编号 | 规则与已实现行为 | 验收标准 |
|---|---|---|
| R01 | 注册账号，用户名归一化为小写并保持唯一 | 合法注册201；大小写等价账号不能重复注册，返回409 USERNAME_TAKEN |
| R02 | 新账号密码8至64字符，UTF-8不超过72字节；称呼非空且最多32字符 | 短密码、空称呼或超限输入400；库中只存BCrypt哈希，响应不含密码或哈希 |
| R03 | 注册后独立登录，凭证有效期7200秒 | 注册响应无token；正确登录200，错误密码401；重启服务后重新登录 |
| R04 | 活动查询需要有效登录，显示容量、报名数、余量和本人的报名ID | 已知活动200；未登录401；不存在的活动404 EVENT_NOT_FOUND |
| R05 | 报名身份来自后端登录态 | 报名正文为{}；不能通过附带userId替别人报名，未知正文字段400 |
| R06 | 同一用户同一活动只能有一条报名 | 首次201；重复409 ALREADY_REGISTERED，记录数不增加 |
| R07 | 活动报名总量不能超过capacity | 容量1、初始无报名时两名用户并发，恰好一个201、一个409 EVENT_FULL，数据库只新增一行 |
| R08 | 用户只能查询自己的报名 | 本人按ID查200；另一账号查同一ID返回404 REGISTRATION_NOT_FOUND |
| R09 | 可查自己的全部报名，以及自己在指定活动的报名 | 列表只含本人记录，按ID倒序；未报名的活动查询返回404 |
| R10 | 账号与报名持久保存，登录会话临时保存 | Java重启后旧token无效，重新登录后仍能找到原账号与报名 |
| R11 | 支持本机独立前端联调 | 5500来源可按配置访问/api；未配置的5501来源不能跨域调用；同源网页正常使用 |

用户名注册规则是去掉首尾空白、转小写后满足`[a-z][a-z0-9_]{2,31}`。演示账号zhh、myh的密码demo123属于既有种子数据，允许继续登录；不能据此认为新注册也接受7字符密码。

## 主要用户流程

1. 用户注册，或选择已有演示账号。
2. 登录取得token，后续请求使用Authorization头。
3. 查询活动；提交报名时由服务端重新检查身份、重复和容量。
4. 成功后得到报名ID，查询记录并在网页显示。
5. 退出时删除当前token；关闭页面后再登录，可以查回持久化记录。

## 边界与约定

- 重复和满员同时成立时，先返回“已报名”，因为实现先检查本人记录。
- 页面显示的余量只供展示，不是预留名额；提交时必须重新判断。
- 活动由种子SQL准备，没有活动新增、修改、取消、支付、候补或报名撤销API。
- 不提供找回密码、邮箱验证、账号禁用、Redis会话、JWT、自动刷新token或多实例一致性会话。

## 最小验收材料

保留注册与登录响应、一次报名201、重复与满员各一次409、本人和他人查询结果、数据库对应行，以及两账号并发结果。样例ID可以写成57，正式验收应使用接口真实返回的ID。

验收用例与已有记录见[测试计划](06_测试计划与验证记录.md)，需求到源码的对应见[追踪矩阵](08_追踪矩阵与现状差距.md)。
