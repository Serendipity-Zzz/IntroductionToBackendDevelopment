# 数据库设计与变更说明

DDL以[01_schema.sql](../项目工程/前后端/backend/sql/01_schema.sql)为准。三张表使用InnoDB、utf8mb4、utf8mb4_0900_ai_ci。完整工程默认库signup_demo，练习工程默认signup_lab。

## 字段字典

### users

| 字段 | 类型与空值 | 约束与用途 |
|---|---|---|
| id | BIGINT，非空 | 主键、自增；新建库中zhh、myh通常为3、4，已有库以查询为准 |
| username | VARCHAR(32)，非空 | 唯一用户名，应用写入前去首尾空白并转小写 |
| display_name | VARCHAR(50)，非空 | 显示称呼；注册API限制最多32字符 |
| password_hash | VARCHAR(100)，非空 | BCrypt哈希；不向API返回 |

### events

| 字段 | 类型与空值 | 约束与用途 |
|---|---|---|
| id | BIGINT，非空 | 主键；由课堂SQL指定，非自增 |
| title | VARCHAR(100)，非空 | 活动名称 |
| capacity | INT，非空 | CHECK capacity > 0 |

### registrations

| 字段 | 类型与空值 | 约束与用途 |
|---|---|---|
| id | BIGINT，非空 | 主键、自增，可能跳号 |
| event_id | BIGINT，非空 | 外键fk_registration_event，关联events.id |
| user_id | BIGINT，非空 | 外键fk_registration_user，关联users.id |
| created_at | DATETIME，非空 | 默认CURRENT_TIMESTAMP；响应为无时区偏移的本地日期时间 |

联合唯一约束`uk_event_user(event_id,user_id)`禁止同一用户重复报名。没有配置级联删除；有关联报名时，不能直接删掉被引用的用户或活动。

## 关系

一个用户可以有多条报名，一场活动可以有多条报名。registrations把两者关联起来。活动容量不是报名表的行数上限约束，由应用事务判断。

```sql
SELECT r.id, u.username, e.title, r.created_at
FROM registrations r
JOIN users u ON u.id = r.user_id
JOIN events e ON e.id = r.event_id
WHERE r.event_id = 10;
```

## 旧库升级注册功能

`CREATE TABLE IF NOT EXISTS`不会修改已经存在的表。旧版users.id没有自增时，启动新程序仍可能登录，但注册插入会失败。

1. 确认要升级的是自己的signup_demo或signup_lab，并备份这次课堂数据。
2. 管理员连接选中对应库，先执行SELECT DATABASE()。
3. 执行03脚本，给users.id增加AUTO_INCREMENT，保留原ID、账号与报名。
4. 检查SHOW COLUMNS FROM users LIKE 'id'包含auto_increment；注册一个新账号并确认ID不覆盖既有账号。
5. 确认原账号能登录、原报名仍在，错误外键引用仍被拒绝。

脚本临时关闭当前连接的FOREIGN_KEY_CHECKS，并恢复原值；若客户端在ALTER错误后停止，重新连接或按脚本提示恢复检查。workshop默认没有ALTER权限，不能用它代替管理员做这一步。

当前没有Flyway/Liquibase或自动版本化迁移。后续变更应新增编号SQL，写明备份、执行、验证和回退办法，不通过删库重建来升级已有数据。

演示账号现统一使用zhh、myh，密码均为demo123。旧账号保留。新建库中两个新账号的用户ID通常为3、4；已有库的编号可能不同，以登录响应user.id或按用户名查询的结果为准。旧库先在所用课堂库执行sql/04_新增演示账号.sql；如users.id尚未自增，先执行03升级脚本。
