# 后端开发与接口调试例会提纲

从前端能做什么、哪些事不能只靠浏览器决定说起。用同一个报名页面依次演示纯前端、内存后端和数据库后端，再一起启动完整工程，把主要上机时间留给Apifox。按150分钟安排，SQL作为课后拓展。

| 时间 | 内容 | 展示与操作 |
|---|---|---|
| 0至30分钟 | 网页能存数据，为什么还要后端 | 纯前端登录、报名；F12全局搜索demo123，定位app.js；Application查看localStorage；两个浏览器各自判断名额 |
| 30至45分钟 | 从Java内存走到数据库 | 内存后端统一处理最后一个名额；刷新仍在，重启Java后报名消失；数据库版只重启Java，再登录查回原记录 |
| 45至60分钟 | 后端、语言、框架与开发流程 | 后端也给手机App、游戏客户端等提供服务；Java与Spring Boot；从需求、接口到实现和验证 |
| 60至80分钟 | 启动完整工程 | 课前完成数据库准备脚本；IDEA运行完整后端8080，VS Code打开5500前端；登录和报名；留出休息与排错时间 |

| 115至140分钟 | 给完整工程加接口，再修错 | 新增registration-status路径；保持原my-registration接口；错误参数返回404，IDEA断点观察，修正后200 |
| 140至150分钟 | 自动检查与SDD | 脚本重跑请求并检查归属；把刚才观察的行为写成验收条件，介绍Spec Kit |

## 三个演示分别回答什么

纯前端回答“浏览器能做到哪一步”。新注册账号在localStorage中以带盐哈希保存，报名在页面内存；F12能看到代码和本地数据。演示密码写在纯前端校验逻辑中是教学设计，不能把这样的校验当成真实权限边界。apiBase等公开地址可见是正常现象。

内存后端回答“有后端就一定能长期保存吗”。Java统一校验身份、处理名额，多浏览器共享数据；页面刷新不清空服务端集合。停止并重启Java后，再登录查看报名为空，说明内存没有持久化。

数据库后端回答“怎样在进程重启后保留业务记录”。报名写入MySQL，只重启Java后重新登录，仍能读回同一个报名ID。现场演示这个效果，不逐条讲建表与SQL。

后端负责统一处理请求和业务，数据库负责持久化业务数据。数据库连接密码、密钥等留在服务端配置中；不是所有前端配置都应该塞进数据库，也不是接上数据库就自动安全。

## 课前准备与上机范围

安装JDK21、IDEA、MySQL、VS Code与Live Server、Apifox，Maven由IDEA或Wrapper提供。先运行快速启动/课前准备数据库.ps1，使用自己的数据库管理员与workshop密码，确认准备完成。这个脚本保留旧账号和报名。

例会上打开完整工程、填运行环境变量、启动服务，先网页联调，再Apifox调试。主线不补SignupRepository的SQL，不要求执行Query Console语句。原有库表说明、SQL增删改查和两句填空保留在Guide第七模块的折叠拓展。

新增接口使用RegistrationStatusController，路径为/api/events/{eventId}/registration-status，避免与完整工程已有my-registration入口冲突。先用已有接口确认记录，加入错误版，观察404，再修正参数。重新运行Java后要重新登录，不能用旧token判断记录是否丢失。
