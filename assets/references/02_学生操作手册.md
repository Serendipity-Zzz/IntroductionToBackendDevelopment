# 报名系统启动与接口调试手册

前半段通过三个版本看后端的作用，后半段使用现成的完整工程实操。SQL与手动建表放在Guide的折叠拓展，先不用逐条执行。

## 1 准备工具和数据库

按HTML实操Guide的课前清单安装JDK21、IDEA、MySQL、VS Code、Live Server和Apifox。前端是原生HTML/CSS/JavaScript，不需要npm install。

确认MySQL服务已运行。在材料根目录打开PowerShell，运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\快速启动\课前准备数据库.ps1
```

按提示输入自己的MySQL管理员密码和workshop密码。已有workshop就用原密码。脚本准备signup_demo和演示数据，不清空旧记录。端口不同可加-DbPort，找不到客户端可加-MysqlExe；完整用法见Guide模块六。

## 2 看三个版本

纯前端版：VS Code打开项目/纯前端版，用Live Server在5501启动。zhh、myh都可用demo123登录。在开发者工具中Ctrl+Shift+F搜索demo123，点击app.js的校验代码；到Application → Local Storage查看当前站点的新注册账号。存储里是带盐哈希，不是新注册账号的明文密码。代码与本地状态可由浏览器使用者查看、编辑，不能承担服务端权限校验。

内存后端版：IDEA打开项目/内存后端版，运行SignupApplication，访问http://127.0.0.1:8082/。报名后刷新网页，记录还在；停止并重启Java，再登录同一演示账号，报名消失。它不连接数据库，新注册账号也只存在于进程内存。

数据库版：完整工程保存账号和报名到MySQL，只重启Java后，重新登录仍能查到同一条报名。这个对照说明持久化，不需要现场抄SQL。

## 3 在IDEA启动完整工程

Open项目/完整工程/pom.xml，等Maven同步完成，Project SDK与Maven JDK都选21。找到SignupApplication.java，通过main旁的运行图标创建Application配置。

主类cn.meeting.signup.SignupApplication，工作目录为完整工程根目录，VM options和Program arguments留空。Environment variables填写：

| 名称 | 值 |
|---|---|
| DB_HOST | 127.0.0.1或自己的数据库主机 |
| DB_PORT | 实际端口，通常3306 |
| DB_NAME | signup_demo |
| DB_USER | workshop |
| DB_PASSWORD | 准备脚本使用的workshop密码 |
| DB_INIT | never |
| SERVER_PORT | 8080 |

Run后查看启动日志，http://127.0.0.1:8080/health应返回status为ok。数据库是否可用，还要用实际登录和活动查询确认。数据库密码放在后端运行配置中，不放前端config.js。

## 4 在VS Code打开前端

Open Folder选择项目/前端联调版，config.js的apiBase为http://127.0.0.1:8080/api。index.html用Live Server打开，确认端口5500。用myh/demo123登录，完成或查询活动1的报名。

活动1已满时先查看已有记录，不必重新建库。需要清理时，确认当前库后使用原90重置脚本；具体SQL和影响放在Guide拓展中。

## 5 用Apifox调试已有接口

导入资料/基础接口.openapi.json，选本地环境，服务前置URL为http://127.0.0.1:8080。环境变量设置event_id=10、username=myh、password=demo123，token、user_id、registration_id先留空。

登录POST /api/auth/login，Body选JSON并引用username、password。200后先手动复制token试一次查询，再在后置操作提取$.token到token、$.user.id到user_id。后续Auth选Bearer Token，只填{{token}}。

GET /api/events/{{event_id}}查活动，再POST /api/events/{{event_id}}/registrations，JSON正文填{}。首次成功201后提取$.id到registration_id，再GET /api/registrations/{{registration_id}}。id应与报名时相同，eventId为10，userId与本次登录提取的一致。

重复报名409 ALREADY_REGISTERED说明已有记录；409 EVENT_FULL说明名额已满，不代表自己报上了。需要重做首次成功时，确认当前库后使用91重置脚本，步骤在Guide折叠拓展中。

注册接口POST /api/auth/register成功后仍要登录。后半段核心练习继续用myh，数字ID从响应提取，不照抄示例4。

## 6 新增接口并修错

完整工程已有my-registration入口，本次另加registration-status路径。将完整工程/课堂文件/RegistrationStatusController.错误.java.txt复制到src/main/java/cn/meeting/signup/，重命名为RegistrationStatusController.java，确认没有.txt后缀。

IDEA停止旧进程、重新Run，再在Apifox登录更新token。新增GET /api/events/{{event_id}}/registration-status，带上{{token}}。myh报过活动10时，错误版仍会返回404 REGISTRATION_NOT_FOUND。

在return行打断点，Debug启动。重新登录后再发送请求，在Variables查看活动ID与用户ID。错误代码把eventId传了两次，第二个参数应为userId。Resume让请求继续，修正后停止旧进程、重新运行并登录，再发送同一GET，应返回200且指向原报名。

## 7 自动检查与拓展

完成新增接口后，在材料根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\资料\自动检查.ps1 -BaseUrl http://127.0.0.1:8080 -CheckAddedEndpoint
```

最后出现All checks passed.，表示脚本中的身份、活动和记录一致性检查通过。它不覆盖全部网页、并发和异常输入；新增需求还要补检查。SQL、数据库关系和旧练习工程填空都保留在Guide第七模块，课后可继续做。
